# 一、时间日期

## 先扫雷：老 `Date` 和 `Calendar` 是古董 ⚠️

Java 1.0 的 `java.util.Date` 和 1.1 的 `Calendar` 设计糟糕（月份从 0 开始、对象可变导致线程不安全），比 JS 的 `Date` 更烂。**新项目只用 Java 8 的 `java.time` 包**——它约等于"官方内置的 dayjs" 🔥。

## 三个主角：LocalDate / LocalTime / LocalDateTime

按"你需要的精度"三选一：

| 类 | 装什么 | 类比 dayjs |
|----|--------|-----------|
| `LocalDate` | 只有日期：2026-07-31 | `dayjs().format('YYYY-MM-DD')` 的实体化 |
| `LocalTime` | 只有时间：18:30:00 | 时分秒 |
| `LocalDateTime` | 日期+时间：2026-07-31T18:30 | `dayjs()` 整体 |

⚠️ 它们**都不带时区**——就像 dayjs 默认的"本地 naive 时间"，时区后面单独说。

## 初始化

```java
import java.time.LocalDate;
import java.time.LocalDateTime;

// 现在（≈ dayjs()）
LocalDateTime now = LocalDateTime.now();

// 指定值（≈ dayjs('2026-07-31')，但参数是数字不会解析错）
LocalDate date = LocalDate.of(2026, 7, 31);        // ⚠️ 月份就是 7！不是 0 起算 😌
LocalDateTime dt = LocalDateTime.of(2026, 7, 31, 18, 30, 0);

// 解析字符串（≈ dayjs 传字符串）
LocalDate parsed = LocalDate.parse("2026-07-31");                       // ISO 格式直接解析
LocalDateTime p2 = LocalDateTime.parse("2026/07/31 18:30",
        DateTimeFormatter.ofPattern("yyyy/MM/dd HH:mm"));               // 其他格式要 formatter
```

## 时间计算：不可变 + 链式 😌

和 dayjs 一样是**不可变对象**，每次计算返回新实例：

```java
LocalDate today = LocalDate.now();

LocalDate nextWeek = today.plusDays(7);        // 加 7 天（≈ dayjs().add(7, 'day')）
LocalDate lastMonth = today.minusMonths(1);    // 减 1 个月
LocalDateTime later = now.plusHours(3).minusMinutes(15);   // 可链式

// 比较（≈ dayjs 的 isBefore/isAfter/isSame）
today.isBefore(nextWeek);     // true
today.isEqual(nextWeek);      // false

// 两个时间的间隔
Period period = Period.between(today, nextWeek);        // 日期差：P7D
period.getDays();                                        // 7
Duration duration = Duration.between(now, later);        // 时间差：PT2H45M
duration.toMinutes();                                    // 165
```

## 格式化：DateTimeFormatter ⚠️

```java
import java.time.format.DateTimeFormatter;

DateTimeFormatter fmt = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

String text = now.format(fmt);                    // 时间 → 字符串："2026-07-31 18:30:00"
LocalDateTime back = LocalDateTime.parse(text, fmt);  // 字符串 → 时间
```

⚠️ **大小写敏感，踩坑高发**：

| 符号 | 含义 | 别写成 |
|------|------|--------|
| `yyyy` | 年 | ~~YYYY~~（那是"周年"，年底会出 bug 💼） |
| `MM` | 月 | ~~mm~~（那是分钟！） |
| `dd` | 日 | |
| `HH` | 24 小时制 | `hh` 是 12 小时制 |
| `mm` | 分钟 | ~~MM~~ |
| `ss` | 秒 | |

`yyyy-MM-dd HH:mm:ss` 背下来，后端出现频率最高的格式串 🔥。

## 时区与时刻 🆕

前端吐槽 JS 时区久矣，Java 的模型更清晰——**naive 时间和带时区时间是两个类型**：

```java
import java.time.*;

// Instant：时间戳（≈ Date.now() 的对象版），全球唯一时刻
Instant instant = Instant.now();
long epochMilli = instant.toEpochMilli();        // 1730000000000，和老 System.currentTimeMillis() 一致

// ZonedDateTime：带时区的完整时间
ZonedDateTime beijing = ZonedDateTime.now(ZoneId.of("Asia/Shanghai"));
ZonedDateTime newYork = beijing.withZoneSameInstant(ZoneId.of("America/New_York"));
// 同一时刻，换个时区看（≈ dayjs.tz()）

// LocalDateTime 和时区互转
LocalDateTime ldt = LocalDateTime.now();
ZonedDateTime zoned = ldt.atZone(ZoneId.of("Asia/Shanghai"));   // 给它装上时区
```

选型一句话：**业务展示用 `LocalDateTime`，存库/传输用 `Instant`（时间戳）或带时区的 `ZonedDateTime`** 🔥。

# 二、IO：输入输出流

## 流的概念：方向以"程序"为参照 ⚠️

IO 流（Stream）是数据在**程序与外部世界**（文件、网络）之间流动的通道。新手最易混的是方向：

```
文件 ──输入流──▶ 程序（内存）   读：把数据"输入"到程序
程序 ──输出流──▶ 文件           写：把数据从程序"输出"到文件
```

⚠️ **输入/输出是站在程序视角说的**：读文件用输入流（数据流进程序），写文件用输出流。和直觉相反，必混一次。

Node 类比：`fs.createReadStream` / `fs.createWriteStream`——概念完全一致 😌。

Java 的流分两族 🆕：

| 家族 | 处理单位 | 基类 | 用途 |
|------|----------|------|------|
| **字节流** | byte（8 位） | `InputStream` / `OutputStream` | 一切文件（图片、视频、压缩包） |
| **字符流** | char（16 位，带编码） | `Reader` / `Writer` | 纯文本（自动处理 UTF-8 等编码） |

**文本用字符流，二进制用字节流**——字符流帮你处理了编码，拿字节流读中文容易乱码 ⚠️。

## 关流与 try-with-resources 🆕🔥

JS 里你从没手动关过流（V8/Node 兜底）；Java 的流是**操作系统资源，不关会泄漏**。老式写法是 finally 里 close，Java 7 起有优雅姿势：

```java
// try-with-resources：括号里的资源在 try 结束时自动关闭 🔥
try (BufferedReader reader = new BufferedReader(new FileReader("a.txt"))) {
    String line = reader.readLine();
    System.out.println(line);
}   // 离开大括号，reader 自动 close，不用写 finally ✅
```

这是 Java 独有的资源管理模式（≈ Python 的 with），**凡是实现 Closeable 的资源都这么开**，后端写文件、连数据库天天见。

## 缓冲流：给流加个"蓄水池"

直接读磁盘是逐字节搬运，慢；缓冲流在内存里开个 8KB 的池子，攒一批再读写，**性能差几十倍** 🔥：

```java
// 装饰器模式：BufferedReader 包在 FileReader 外面
BufferedReader reader = new BufferedReader(new FileReader("a.txt"));
//                       ↑ 缓冲装饰      ↑ 基础字符流
```

JS 用户秒懂：就是 Node Stream 内部的 highWaterMark 缓冲，只不过 Java 要手动包一层。经典组合 `new BufferedReader(new FileReader(...))` 眼熟即可。

## Files 工具类：现代文件操作的主角 🔥

上面那些流式写法是"理解原理"，**日常开发 90% 的场景用 `java.nio.file.Files` 一行解决**（≈ Node 的 `fs.readFileSync` 家族）：

```java
import java.nio.file.*;

Path path = Path.of("data", "note.txt");    // 路径对象（≈ path.join，自动适配系统分隔符）

// 读（Java 11+）🔥
String content = Files.readString(path);              // 整个文件读成字符串 ≈ fs.readFileSync(p, 'utf8')
List<String> lines = Files.readAllLines(path);        // 按行读成 List

// 写 🔥
Files.writeString(path, "Hello IO");                  // 写字符串（默认覆盖）
Files.writeString(path, "追加一行", StandardOpenOption.APPEND);   // 追加模式

// 创建与判断
Files.createDirectories(Path.of("data/logs"));        // 递归建目录 ≈ fs.mkdirSync(p, {recursive: true})
Files.createFile(path);                               // 建文件（已存在会报错）
Files.exists(path);                                   // 是否存在
Files.size(path);                                     // 文件大小

// 复制 / 移动 / 删除
Files.copy(path, Path.of("backup/note.txt"), StandardCopyOption.REPLACE_EXISTING);
Files.move(path, Path.of("data/note-new.txt"));
Files.delete(path);                                   // 不存在会报错；Files.deleteIfExists 更稳 ⚠️

// 遍历目录
Files.list(Path.of("data")).forEach(p -> System.out.println(p));       // 一层
Files.walk(Path.of("data")).forEach(p -> System.out.println(p));       // 递归所有层
```

⚠️ 这些方法抛的都是**受检异常** `IOException`——编译器强制你处理（下一章异常处理的实战预演，学习阶段方法上加 `throws IOException` 即可）。

## 序列化：对象 ⇄ 字节流

**是什么**：把内存中的对象变成字节流（存盘/网络传输），需要时再还原——≈ JS 的 `JSON.stringify` / `JSON.parse`，但序列化的是**对象本身**（含类型信息），不是 JSON。

```java
// 1. 类要实现 Serializable 接口（只是个标记，无方法）
public class User implements Serializable {
    private static final long serialVersionUID = 1L;   // 版本号，防类变更后反序列化失败 💼
    private String name;
}

// 2. 序列化（对象 → 文件）
try (ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("user.data"))) {
    oos.writeObject(user);
}

// 3. 反序列化（文件 → 对象）
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("user.data"))) {
    User u = (User) ois.readObject();
}
```

🔥 **现实情况诚实说**：原生序列化（安全漏洞多、跨语言不认）在现代后端已经边缘化——实际项目里对象传输都序列化为 **JSON**（Spring 默认用 Jackson 库，Spring Boot 章节见）。原生序列化**理解概念即可**，知道 `Serializable` 是干嘛的、为什么实体类常挂个 `serialVersionUID`。

## 对比总表

| 需求 | JS / Node | Java |
|------|-----------|------|
| 当前时间 | `dayjs()` / `new Date()` | `LocalDateTime.now()` |
| 时间加减 | `dayjs().add(7, 'day')` | `plusDays(7)`（不可变链式 😌） |
| 格式化 | `dayjs().format(...)` | `DateTimeFormatter.ofPattern`（⚠️ MM 月 mm 分） |
| 时间戳 | `Date.now()` | `Instant.now()` / `toEpochMilli()` |
| 时区 | dayjs timezone 插件 | `ZonedDateTime` + `ZoneId`（内置 🆕） |
| 读文件 | `fs.readFileSync(p, 'utf8')` | `Files.readString(path)` 🔥 |
| 写文件 | `fs.writeFileSync` | `Files.writeString` |
| 建目录 | `fs.mkdirSync(p, {recursive:true})` | `Files.createDirectories` |
| 流 | createReadStream（自动缓冲） | 输入/输出流 + 手动包缓冲流 |
| 资源释放 | 无需操心 | **try-with-resources** 🆕🔥 |
| 对象序列化 | `JSON.stringify` | `ObjectOutputStream`（现实用 Jackson/JSON） |

## 练习

1. 时间综合题：计算你出生到今天一共多少天（`Period` 或 `ChronoUnit.DAYS.between`），并打印下一个生日是周几（`getDayOfWeek`）；最后用 `yyyy年MM月dd日 E` 格式输出（E 是星期）。
2. 文件综合题：用 `Files` 完成——创建目录 `logs`、写入三行文本到 `logs/app.log`、读取并按行打印、复制为 `app-backup.log`、最后删除整个目录。要求用 try-with-resources 或 Files 的一行方法，不许手动 close。
3. 思考题（不编码）：为什么读中文文本文件要用字符流而不是字节流？如果你必须用字节流读一个 UTF-8 的中文文件，要怎么避免乱码？

## 本章总结

- 时间只用 `java.time`：`LocalDateTime`（业务展示）+ `Instant`（存库传输）+ `ZonedDateTime`（时区）；不可变链式计算 ≈ dayjs 😌
- 格式化 `yyyy-MM-dd HH:mm:ss` 背下来，**MM 是月、mm 是分** ⚠️
- 流的方向站在程序视角：读=输入流、写=输出流；文本用字符流、二进制用字节流；缓冲流提性能
- **资源必须关闭，用 try-with-resources** 🆕🔥
- 日常文件操作首选 `Files` 一行方法；序列化理解概念即可，现代实践是 JSON（Jackson）
